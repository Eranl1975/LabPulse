# LabPulse v7.0 — Diagnostic Quality Upgrade

## Implementation prompt

### Context

A GC-MS user asked LabPulse about a ghost peak appearing at the start of every
run, in both the FID trace and the TIC, whose mass spectrum shows CO₂ and argon.
The report that came back
(`labpulse-report-GC-2026-09-28.txt`) failed in three distinct ways. Each is a
defect in a different layer, and each must be fixed at that layer rather than
patched in the renderer.

**Defect 1 — no mass-spectral diagnostics.** The user runs a hyphenated
instrument and explicitly described mass-spectral evidence (CO₂ + Ar at the
solvent front, present in both FID and TIC). CO₂ *plus argon* is the signature of
atmospheric air, and "present in FID *and* TIC" localises the source upstream of
the detector — both are decisive discriminators. The report contained no
mass-spectral check whatsoever: no background subtraction, no air/water
tune check, no ion-identity table, no FID-vs-TIC localisation. The knowledge base
and the generic procedures are detector-blind: the GC procedure set assumes an
FID-style detector and the MS content only activates when the user picks the
`GCMS` technique, which this user did not.

**Defect 2 — four identical hypotheses.** Section 4 listed *contaminated inlet
liner*, *septum bleed*, *column bleed* and *solvent impurity* as four separate
ranked entries with byte-identical supporting evidence, diagnostic test and
expected result, because `buildHypotheses()` in `agents/ranking/index.ts` emits
one hypothesis per `likely_cause` string while all four causes originate from a
single knowledge item. Four causes that one blank injection discriminates are one
diagnostic step, not four, and presenting them as four is what makes the standard
report unreadable.

**Defect 3 — no structured column input.** `column` is a single free-text box, so
the user typed nothing, the field was flagged critical-missing, and confidence was
capped at 60%. Column chemistry and dimensions are the highest-value context a
chromatography answer can have, and free text is the wrong affordance for them.

### Required changes

**1. Detector-aware diagnostics (`lib/detector-addenda.ts`, new)**

Infer the detectors actually in play from the technique, the technique-specific
detector context fields (`gcDetectorType`, `detectorType`, `semDetector`, …) and
the free text of the symptom and method (`TIC`, `m/z`, `mass spec`, `MSD`, `SIM`,
`full scan`, `DAD`, `ELSD`, …). Infer `ms` for `GCMS`/`LCMS` unconditionally, and
for any technique whose detector field or free text names an MS.

Expose `appendDetectorAddenda(answer, query)`, called from
`runTroubleshootingPipeline` after the generic-procedure merge and before the
document merge. For each inferred detector it appends detector-specific
hypotheses, checks and follow-up questions for the matched issue family, and
only where that content is not already present. The addendum is evidence tier 6
(manufacturer-independent best practice) and must be cited as such — it never
silently raises confidence.

Cover at minimum: MS, FID, UV/DAD, ECD, TCD, ELSD/CAD/RID, FLD. The MS addendum
must cover background/ghost peaks, signal loss, mass accuracy, carryover, noise
and retention-time shift, and the background/ghost-peak entry must include the
air-ingress ion table (m/z 28/32 at ≈4:1, 40 Ar, 44 CO₂, 18 H₂O), the
column-bleed and septum-bleed ion series (207/281/355, 73/147), the
phthalate series (149/167/279), background subtraction at the peak apex, the
air/water tune check, and the FID-versus-TIC localisation test.

**2. Hypothesis clustering (`lib/hypothesis-clustering.ts`, new)**

`clusterHypotheses(hypotheses)` merges hypotheses that share a normalised
diagnostic test into one entry carrying `grouped_causes: string[]` (added to the
`Hypothesis` type as an optional field, so existing producers stay valid). The
merged entry takes the highest probability, the union of supporting and
contradicting evidence, and the rank of its first member; ranks are renumbered
contiguously. Apply it in `rankItemsV2` and to the AI-fallback output, so every
producer benefits.

Replace the `expected_result` filler string
("If this cause is correct, the diagnostic should confirm the issue") with text
that actually discriminates, and have the formatters omit the line when it is
empty rather than print a placeholder.

**3. Structured column selector (`lib/column-catalog.ts`, `components/ColumnSelector.tsx`, new)**

A catalogue of real commercial stationary phases keyed by technique family (GC,
LC/reversed-phase/HILIC/chiral/SEC/IEX, IC, SFC), each with vendor, chemistry and
a short descriptor, plus the dimension option lists for that family: length, inner
diameter and film thickness for GC; length, inner diameter and particle size for
LC-type columns.

`ColumnSelector` renders a **Browse catalogue** button over a searchable,
grouped list, three dimension dropdowns whose labels and units follow the
technique family, and keeps free-text entry working for columns not in the
catalogue. It composes the canonical string into the existing `column` field
(`DB-5ms 30 m × 0.25 mm × 0.25 µm`) so nothing downstream changes, and also emits
the parts as `column_phase`, `column_length`, `column_id`, `column_film` /
`column_particle` in `extra_context` for ranking and the AI prompt.

Wire it in `QueryFormStep2.DynamicField` by field key, not by technique, so every
technique that has a `column` field picks it up automatically.

**4. Report length (`agents/presentation/formatters/standard.ts`)**

Clustering does most of the work. Beyond it: render grouped causes as one block
with a candidate-cause list and a single shared diagnostic test; drop the
auto-generated per-action verification filler in favour of the measurable
acceptance criteria plus one instruction; and move the printable checklist out of
the standard text, where it repeated sections 5 and 6 verbatim, keeping it in the
answer payload for the PDF and print views. Deduplicate the uncertainty list.

### Acceptance criteria

1. A `GC` query whose text mentions the TIC, a mass spectrum or an MS detector
   returns mass-spectral checks, including the air-ingress ion table and the
   FID-vs-TIC localisation test.
2. Causes sharing one diagnostic test appear as a single ranked block naming all
   of them; no two blocks in a report repeat the same diagnostic test.
3. The column field offers a catalogue and three dimension dropdowns for every
   technique that has a column, and a catalogue selection satisfies the
   `column` critical-field check.
4. `npx tsc --noEmit` clean, full vitest suite green with new tests covering
   each of the four changes, `next build` succeeds.
5. Shipped to GitHub, deployed on Vercel, with the Supabase schema confirmed
   unchanged or migrated.
